## 2. Product overview

**Pitch.** A fast, movement-driven free-for-all arena shooter in the lineage of Quake, Unreal Tournament, and Titanfall. You and 1 to 11 AI bots drop into stylized low-poly arenas and fight for the highest score. Speed is skill: bunnyhopping, slide-hopping, wall-running, and a grapple hook let good players dominate every fight.

**Pillars**

1. **Movement is the skill ceiling.** Every system rewards speed and flow.
2. **Readable at speed.** Flat colors, strong silhouettes, bright emissive trim, clear audio cues.
3. **Instant loops.** Menu to match in under 5 seconds. Death to respawn in about 2 seconds. Match restart in one click.
4. **Everything generated.** No imported content; the whole game is code.

**Platform.** Windows PC, mouse and keyboard (must also run on Linux and macOS without code changes). Controller support is out of scope.

**Modes (all vs bots, all FFA).**

- Deathmatch: first to the kill limit or highest score at time limit.
- Practice Range: a no-pressure movement and aim sandbox with target dummies, speedometer, and a movement challenge course.
- Multiplayer menu entry exists but is disabled with a "Coming soon" label. The architecture must be network-ready (Section 5) but no networking code is written.

**Content summary.** 7 weapons, 8 pickup types, 3 arenas plus the practice range, 4 bot difficulty levels, 12 bot names/colors, full menu flow, rebindable controls, settings persistence, generated SFX and music, particles and screen effects, scoreboard, kill feed, medals, results screen, automated test suite, export presets, and CI workflow file.

## 5. Architecture (network-ready, single-player now)

The game must later gain online multiplayer without a rewrite. Obey these rules:

- **`Fighter`** (`CharacterBody3D`) is the single class for humans and bots. It owns a `MovementController`, `HealthComponent`, `WeaponInventory`, `FighterVisual`, an `id: int`, `display_name`, `color`, and an `input_source: InputSource`.
- **`InputFrame`** (plain class, reused per tick): `move: Vector2`, `look_delta: Vector2` (yaw and pitch radians this tick), `jump_pressed`, `jump_held`, `crouch_pressed`, `crouch_held`, `fire_pressed`, `fire_held`, `alt_pressed`, `alt_held`, `grapple_pressed`, `grapple_held`, `weapon_select: int` (0 for none, 1 to 7), `weapon_next`, `weapon_prev`, `weapon_last`.
- **`InputSource`** base class with `sample(dt: float, fighter: Fighter) -> InputFrame`. Implementations: `PlayerInput` (reads Godot Input), `BotInput` (wraps `BotBrain`), `ReplayInput` (plays a scripted array of frames, used by tests), `RemoteInput` (stub that only documents the future interface).
- **`MatchManager`** is the only authority on shared state: health changes, deaths, scores, respawns, pickups, timers, match end. All state mutations go through methods with the prefix `auth_` (for example `auth_apply_damage(victim_id, DamageInfo)`, `auth_request_respawn(id)`, `auth_collect_pickup(id, pickup_id)`). Fighters and weapons call these instead of mutating each other. Later these become RPCs.
- **Cosmetic reactions** (sounds, particles, kill feed, HUD flashes) listen to `Events` signals, never to direct calls from gameplay code. Gameplay emits; presentation reacts.
- **`Events` signals (minimum):** `fighter_spawned(id)`, `fighter_damaged(victim_id, attacker_id, amount, hit_pos, is_head)`, `fighter_killed(victim_id, killer_id, weapon_id, is_head)`, `fighter_respawned(id)`, `weapon_fired(id, weapon_id, origin, dir)`, `weapon_switched(id, weapon_id)`, `pickup_collected(id, pickup_type, pos)`, `pickup_spawned(pickup_type, pos)`, `grapple_attached(id, anchor)`, `grapple_released(id)`, `fighter_landed(id, speed)`, `fighter_slide_started(id)`, `fighter_wallrun_started(id)`, `explosion(pos, radius, owner_id)`, `match_started`, `match_countdown(seconds_left)`, `match_ended(results)`, `score_changed(id, score)`, `medal_awarded(id, medal_name)`, `hit_confirmed(attacker_id, is_kill, is_head)`.
- **`DamageInfo`** class: `amount`, `attacker_id`, `victim_id`, `weapon_id`, `hit_pos`, `impulse: Vector3`, `is_head`, `is_self`, `is_splash`.
- **Time:** use `Engine.physics_ticks_per_second` based deltas. Never use wall-clock time for gameplay.

## 6. Movement specification (the heart of the game)

Implement `MovementController.step(fighter, frame, dt)` with all tunables in `MovementConfig` (a `Resource` with exported fields, plus a default `.tres` generated in code). Use `CharacterBody3D` with `motion_mode = GROUNDED`, `floor_max_angle = 50 degrees`, `floor_snap_length = 0.5`, `floor_stop_on_slope = false`, `floor_constant_speed = false`, `max_slides = 6`, `safe_margin = 0.001`. Do your own velocity math, then call `move_and_slide()` once per tick. Units are meters and seconds; physics tick is 120 Hz.

**Body.** Standing capsule: height 1.8, radius 0.4, eye height 1.62. Crouch and slide capsule: height 1.0, eye height 0.8. Changing height must check headroom with a shape cast before standing up.

**Default config values**

| Parameter | Value |
| --- | --- |
| gravity | 24.0 |
| ground\_speed (max run) | 9.0 |
| crouch\_speed | 4.5 |
| ground\_accel | 12.0 |
| ground\_friction | 6.0 |
| stop\_speed | 2.5 |
| jump\_velocity | 8.6 (about 1.5 m jump height) |
| air\_accel | 20.0 |
| air\_wish\_cap | 1.0 |
| jump\_buffer\_time | 0.10 s |
| coyote\_time | 0.08 s |
| max\_speed\_hard\_cap | 35.0 |

**Core accelerate function (Quake style).**

```
func accelerate(vel: Vector3, wish_dir: Vector3, wish_speed: float, accel: float, dt: float) -> Vector3:
    var current: float = vel.dot(wish_dir)
    var add_speed: float = wish_speed - current
    if add_speed <= 0.0:
        return vel
    var accel_speed: float = minf(accel * wish_speed * dt, add_speed)
    return vel + wish_dir * accel_speed
```

**Grounded.** Apply friction first: `speed = horizontal speed; drop = max(speed, stop_speed) * friction * dt; scale velocity by max(speed - drop, 0) / speed`. Then `accelerate(vel, wish_dir, ground_speed (or crouch_speed), ground_accel, dt)`. Keep the fighter glued to slopes with floor snapping unless a jump was started this tick.

**Air.** No friction. Call `accelerate(vel, wish_dir, min(wish_speed, air_wish_cap), air_accel, dt)` where `wish_speed = ground_speed * input magnitude`. Because the cap limits projected speed, strafing with mouse turns while holding a perpendicular key gains speed (strafe-jumping). Do NOT add any extra air-control that breaks this behavior.

**Bunnyhopping.** Jump input is buffered for 0.10 s. If `jump_held` and the fighter lands, the jump fires on the first tick of landing **before friction is applied**, so no speed is lost. Setting `auto_bhop` (default ON): holding jump auto-rehops. If OFF, the player must press jump within the buffer window. Coyote time allows a jump for 0.08 s after leaving a ledge.

**Tuning target (assert in tests).** Starting from 9 m/s, with ideal alternating strafe input (scripted replay with air-strafe yaw sweeps), the fighter reaches at least 16 m/s horizontal within 3 seconds and never exceeds the hard cap. Pure forward-hopping without strafing must NOT gain speed beyond ground\_speed plus 5 percent.

**Slide.**

- Trigger: `crouch_pressed` while grounded and horizontal speed >= 6.5. Cooldown 0.8 s after a slide ends.
- On start: one-time boost `speed = min(speed * 1.15, 14.0)` in the current travel direction, capsule shrinks, camera lowers smoothly.
- During: friction 1.0 (instead of 6.0), steering accel 2.0 limited to turning the velocity (no speed gain from input), and slope physics: add `gravity projected along the floor plane` so downhill slides accelerate and uphill slides decelerate.
- End when speed < 3.5, crouch released, or airborne for more than 0.25 s. Ending below crouch speed returns to normal crouch.
- **Slide-jump:** pressing jump during a slide jumps with full jump height, keeps all speed, and adds 8 percent (capped by the hard cap). Chain limit: the bonus applies only if the previous slide-jump was more than 0.6 s ago.
- Standing crouch (speed under 6.5): crouch\_speed 4.5, small hitbox, no slide.

**Wall-run.**

- Conditions: airborne for at least 0.15 s, horizontal speed >= 5, a wall within 0.7 m on the left or right (two horizontal raycasts perpendicular to facing, wall normal with |y| < 0.3), and the player is holding a movement key toward or along the wall.
- Effects: gravity scale 0.15, velocity projected onto the wall plane, speed along the wall accelerates toward 11 m/s, maximum duration 1.6 s (then the fighter drops off), camera roll 12 degrees away from the wall, small wall-hugging force of 2 m/s toward the wall to maintain contact.
- Cooldown: after ending a wall-run, the same wall cannot be re-run for 0.35 s.

**Wall-jump.** Pressing jump while wall-running or while airborne within 0.5 m of a wall: `vel = wall_normal * 7.0 + Vector3.UP * 8.0 + horizontal_tangent_velocity * 0.9`. Maximum 3 wall-jumps between ground contacts (counter resets on landing or grapple release).

**Mantle.**

- Trigger: airborne (or grounded and pressing jump into a wall), moving toward a wall with `forward` input, upward velocity >= -2, and a ledge exists whose top is between 0.5 m and 1.9 m above the feet, with top surface normal.y > 0.7 and enough clearance for the crouch capsule.
- Detect with a forward ray at chest height and a downward ray from above the ledge candidate.
- Execution: over 0.25 s ease the fighter position onto the ledge (disable gravity), then restore 70 percent of the pre-mantle horizontal speed along the facing direction. Cancel if blocked.

**Grapple hook.**

- Press `grapple`: raycast 45 m from the camera along the crosshair against `world`. On hit, attach an anchor point. Fighters cannot be grappled.
- While attached and held: acceleration of 38 m/s^2 toward the anchor, speed along the rope capped at 28 m/s. Rope length is set at attach distance and shortens at 12 m/s while held (minimum 3 m). If the fighter exceeds rope length, remove the outward radial velocity component (swinging) and softly pull inside.
- Release by letting go of `grapple` or pressing `jump` (jump release adds +2 m/s upward). Velocity is fully preserved on release.
- Maximum attached time 4 s, then auto-release. Cooldown 1.5 s after release (shown as a HUD ring).
- Visual: a thin emissive rope from the left hand to the anchor with a small flare at the anchor, plus a thunk sound on attach.

**Landing and camera.**

- Landing speed event emits `fighter_landed` with downward speed; the camera dips 0.08 m over 0.12 s scaled by impact (max at 18 m/s).
- No fall damage.
- Camera FOV: base 100 (settings range 80 to 130), plus up to +12 degrees as horizontal speed rises from 9 to 22 m/s, lerped smoothly. Strafe tilt up to 1.5 degrees; wall-run roll up to 12 degrees; sliding lowers the camera. No head bob.
- Mouse look: yaw and pitch from `InputEventMouseMotion.relative * sensitivity * 0.0022` radians, pitch clamped to +/-89 degrees. No smoothing or acceleration.

**Optional (FALLBACK: skip if stuck):** *surf ramps*. Static surfaces with slope between 50 and 80 degrees marked as `surf` apply no friction and project velocity along the plane, letting players ride them. Include one surf section in the Sprawl map only after everything else is done and passing.

**Debug overlay (F3).** Shows speed (m/s and ups), vertical speed, state (grounded, air, slide, wallrun, mantle, grapple), FPS, physics tick time, bot count, and active timers. Always available in builds as a toggle but off by default.

**Hit detection.**

- Every `Fighter` has two `Area3D` hit volumes on layer `hitboxes`: a body capsule (matches the standing capsule, shrinks when crouching) and a head sphere (radius 0.22 m at eye height) with metadata `part = head`. Both reference their owner `Fighter`.
- Hitscan: `PhysicsRayQueryParameters3D` from the camera along the aim direction, mask `world + hitboxes`, `collide_with_areas = true`, excluding the shooter. Resolve the closest hit; head vs body from metadata. Railgun loops the ray forward past each fighter hit (max 3) until world is hit. Produce a `DamageInfo` and call `MatchManager.auth_apply_damage`.
- Hitscan origin is the camera, so what the crosshair shows is what is hit. The visual tracer starts at the weapon muzzle and ends at the hit point.
- Projectiles use swept rays from the previous position to the new position each physics tick (no tunneling), explode on world or hitbox contact, and expire after their lifetime. Rockets spawn from a slightly offset muzzle but are aim-corrected to the crosshair target point.
- Splash damage: sphere shape query on `hitboxes`, then a line-of-sight check to the fighter center against `world`. Damage falls off linearly with distance. Apply impulse direction from explosion center to fighter center, magnitude scaled by falloff, to the fighter velocity (this produces rocket jumps and knockback on enemies).
- Spread randomness uses the `MatchManager` seeded RNG so tests are repeatable.

**Handling rules.**

- Weapon switch time 0.25 s (cannot fire while raising). Mouse wheel cycles owned weapons with ammo; `weapon_last` swaps to the previous weapon.
- Auto-switch to a newly collected weapon only if the current weapon is Blade or Arc Pistol and the setting `auto_switch_on_pickup` (default ON) is enabled. When the current weapon runs out of ammo, auto-switch to the best owned weapon with ammo.
- Firing is semi-auto for Shotgun, Rocket, Railgun, Pistol, Blade (holding fire repeats at the fire interval), and full-auto for SMG and Plasma.
- Ammo is a per-weapon pool; no reloading.

**Viewmodels (`viewmodel.gd`).** Build each weapon from 4 to 10 primitive meshes (boxes, cylinders, prisms) with flat colors and an emissive accent line. Render in a dedicated `SubViewport` with its own camera at FOV 70 composited over the main view so weapons never clip into walls. **FALLBACK:** materials with `no_depth_test = true` and ascending `render_priority`. Procedural animation only: recoil via spring-damper offset and rotation, raise/lower on switch, subtle sway from look delta and strafe velocity, slide pose (weapon tilts), and a very small idle bob scaled by speed.

**Weapon FX.**

- Muzzle flash: emissive quad plus a brief `OmniLight3D` (0.05 s).
- Tracers: thin emissive stretched box traveling at 300 m/s visual speed from muzzle to hit point, colored by weapon (pistol cyan, SMG yellow, shotgun white, rail magenta).
- Impacts: sparks (`GPUParticles3D` pooled), a short flash, and a bullet-hole `Decal` from a pool of 48 (procedurally generated 64x64 texture, fades after 12 s). Fighter hits spawn red-white cube sparks instead of decals.
- Explosion: expanding emissive sphere, shockwave ring, fire particles, smoke particles, `OmniLight3D` flash, and screen shake scaled by distance.
- Plasma: glowing bolt with a trailing particle strip and a small splash flash on impact.

## 8. Pickups, health, and armor

**Damage pipeline (in this order):** raw damage -> attacker powerup multiplier -> armor absorption (armor absorbs 66 percent of the damage until armor reaches 0; the absorbed amount is subtracted from armor) -> remainder to health. Self-damage from splash uses the self factor. Spawn protection and invulnerability ignore everything.

**Stats.** Health starts at 100, armor at 0. Maximum health 100 (200 with Mega Health). Health above 100 decays at 1 per second. Maximum armor 100.

| Pickup | Effect | Respawn | Visual |
| --- | --- | --- | --- |
| Stim | +25 health (up to 100) | 15 s | small green cross, rotating, bobbing |
| Medkit | +50 health (up to 100) | 30 s | large green cross |
| Mega Health | +100 health (up to 200) | 60 s | large pulsing green orb with ring |
| Armor Shard | +25 armor (up to 100) | 15 s | small blue shard |
| Armor Plate | +50 armor (up to 100) | 30 s | large blue plate |
| Ammo Box | Gives about 40 percent of max ammo for each owned ammo weapon | 20 s | yellow crate |
| Weapon Pickup | Grants that weapon plus its starting ammo (adds ammo if already owned) | 25 s (Rocket and Rail 30 s) | weapon model rotating, orange ring |
| Powerup | Overcharge: 2x outgoing damage for 20 s (respawn 120 s). Haste: +25 percent speed and fire rate for 20 s (respawn 90 s) | as listed | purple (Overcharge) or cyan (Haste) glowing octahedron with a beam to the sky |

**Rules.**

- Pickups are `Area3D` on layer `pickups`. Collection goes through `MatchManager.auth_collect_pickup`. A pickup is not consumed if it would give nothing (full health for a Stim, and so on), except Mega Health, powerups, and weapons with ammo to give.
- Collected pickups become a translucent ghost outline with a ring that fills as the respawn timer progresses (visible from a distance, serving as timing information).
- Death drop: a dying fighter drops a backpack containing its currently held non-starter weapon and 50 percent of its ammo for that weapon. Backpacks expire after 20 s.
- Powerup state shows on the HUD with a timer and on the fighter model as a colored aura. A global text announcement fires when a powerup is picked up and when it respawns.
- Each map defines pickup placements by marker lists in its map script; the `PickupSpawner` instantiates them and runs respawn timers inside `MatchManager`.

## 9. Fighters, death, respawn, scoring

- **Death.** At 0 health: emit `fighter_killed`, drop a backpack, hide the model and burst it into 12 to 16 colored cube `RigidBody3D` debris (layer `debris`, collide with world only, despawn after 4 s, pooled), and play a death sound. The human player's camera detaches into a short third-person death cam that orbits to look at the killer for up to 2 s.
- **Respawn.** Automatic after 2.0 s. The human can press fire after 1.0 s to respawn early. Spawn point selection (`spawn_system.gd`): score every spawn point by minimum distance to living enemies, penalize points that have line of sight to any enemy within 40 m, add 0 to 5 m random noise from the seeded RNG, and avoid the point this fighter used last time. Fighters face the spawn marker's yaw.
- **Spawn protection.** 2.0 s invulnerable with a shimmering shield shader. It ends early when the protected fighter fires a weapon (after a 0.5 s minimum).
- **Scoring.** +1 per kill. Suicide (own splash, kill volume, falling out of the map) is -1. If a fighter dies to the void within 4 s of being damaged by an enemy, the last attacker gets the kill credit. Tiebreaks: fewer deaths, then earlier time of last kill.
- **Medals** (`medals.gd`, shown as a HUD text pop-up and a chime): First Blood, Double Kill (2 kills within 3 s), Triple Kill (3 within 3.5 s), Mega Kill (4 within 4 s), Rampage (5 kills without dying), Unstoppable (10 without dying), Headhunter (3 headshot kills in one life), Airborne (kill while airborne for over 0.5 s), Rocketeer (airborne splash kill), Hooked (kill within 2 s of releasing the grapple), Skewer (railgun double-pierce kill), Comeback (kill the current score leader while you are in last place or tied for it), Denied (kill an enemy who holds an active powerup).
- **Out of bounds.** Each map has a kill volume below the playable area and optional hazard volumes (for example, the Foundry pit lava). Entering a kill volume triggers death with the attribution rules above.
- **Fighter appearance (`fighter_visual.gd`).** Built from primitives: capsule torso, sphere head with a dark visor strip, box limbs for arms and legs, a backpack box, and a held weapon model matching the current weapon. Per-fighter primary color plus an emissive accent. Procedural animation only: leg swing proportional to speed, lean into velocity direction, crouch squash, slide pose (tilted back), airborne tuck, weapon recoil, hit flash (white for 0.06 s), and a faint colored trail when speed exceeds 18 m/s. The human player's own body is hidden in first person (but visible in the death cam).

## 10. Bots

Bots are `Fighter`s driven by `BotInput`, which wraps `BotBrain`. They use the **exact same movement controller, weapons, and damage rules** as the player and have no hidden advantages: they perceive through line-of-sight checks only (no wallhacks), aim with limited speed and error, and react with a delay.

**Difficulty profiles (`BotProfile` resources).**

| Parameter | Rookie | Veteran | Elite | Nightmare |
| --- | --- | --- | --- | --- |
| Reaction time (s) | 0.55 | 0.35 | 0.22 | 0.12 |
| Aim error (degrees) | 6.0 | 3.5 | 1.8 | 0.8 |
| Aim tracking speed (deg/s) | 120 | 220 | 360 | 600 |
| View FOV (degrees) | 110 | 120 | 130 | 140 |
| View range (m) | 40 | 55 | 70 | 90 |
| Target memory (s) | 2 | 3 | 4 | 5 |
| Projectile lead accuracy | 0.3 | 0.6 | 0.85 | 1.0 |
| Bunnyhop skill (0 to 1) | 0.0 | 0.4 | 0.8 | 1.0 |
| Slide usage | 0.1 | 0.4 | 0.7 | 1.0 |
| Grapple usage | 0.0 | 0.3 | 0.7 | 1.0 |
| Wall-run usage | 0.0 | 0.2 | 0.6 | 0.9 |
| Flee health threshold | 35 | 30 | 25 | 20 |
| Dodge intensity | 0.3 | 0.5 | 0.8 | 1.0 |

Each bot gets +/-10 percent random variation per numeric parameter (seeded). The match setup also offers **Mixed** (each bot randomly picks a neighboring difficulty).

**Names and colors.** `bot_names.gd` holds 12 entries: Vex, Juno, Kilo, Rook, Nyx, Pike, Slate, Orion, Echo, Tango, Wren, Blitz. Assign each a distinct high-contrast primary color from `ui_theme.gd`'s palette. Bots appear in the scoreboard and kill feed like players.

**Perception (`bot_perception.gd`).**

- Each bot updates perception every 0.1 s, staggered by fighter id so the load is spread across ticks. Maximum 4 raycasts per bot per update.
- A fighter is visible if inside the view cone and range, with an unobstructed ray to the head or torso point.
- Hearing: gunshots within 35 m, explosions within 50 m, and grapple attach sounds within 25 m create an `Investigate` stimulus at the source position.
- Memory: keep last seen position, velocity, and timestamp per enemy for `memory_time`. Taking damage reveals the attacker direction as a stimulus.
- A newly seen enemy is not engaged until `reaction_time` has elapsed.

**Decision making (`bot_brain.gd`).** Utility-based goal selection every 0.25 s with hysteresis (switch only if the new best utility exceeds the current by 20 percent, or the current goal is completed or invalid).

| Goal | Utility sketch |
| --- | --- |
| Engage | High when an enemy is visible or recently seen, a weapon with ammo is available, and health is above the flee threshold. Raised by low enemy health and own powerup. |
| GrabItem | `need * value / (distance + 10)`. Health value scales with missing health, armor with missing armor, weapon with weapons not owned, powerups very high. Considers pickup respawn timers (heads toward soon-to-spawn pickups). |
| Retreat | When health is below the flee threshold and enemies are near: path toward the nearest health pickup or away from threats. |
| Investigate | Move toward the most recent sound or last-seen position. |
| Roam | Visit random waypoints weighted toward map areas with pickups and toward the score leader (Nightmare and Elite hunt the leader). |
| Reposition | During combat, move to high ground or cover if being out-aimed (taking more damage than dealing). |

**Navigation (`bot_navigator.gd`).** Use the map's `WaypointGraph` (an `AStar3D` generated by `map_builder.gd`, Section 11). Link types: `WALK`, `JUMP` (needs a jump at the link start), `DROP` (walk off a ledge), `GRAPPLE` (anchor position in link metadata), `WALLRUN` (optional, only if generation supports it). Path requests happen on goal change or every 0.5 s, with a global budget of 2 path queries per physics tick across all bots. Follow the path with an arrival radius of 1.5 m, smoothing corners by looking 2 waypoints ahead. The navigator outputs: desired move direction, and `jump_now`, `slide_now`, `grapple_now` flags.

**Movement technique execution.**

- **Bunnyhop and air-strafe** (when the `bhop_skill` roll passes and the path segment ahead is nearly straight, angle under 20 degrees): hold jump, and while airborne alternate the strafe key (left or right) in the direction of the needed turn while rotating yaw toward the path heading by a small angle per tick (`yaw_rate = k * dt`, where k scales with skill). Goal: Nightmare reaches 15 m/s or more on long straight routes, Veteran 11 to 13 m/s.
- **Slide:** begin when speed is over 6.5 m/s in a corridor, downhill, or while strafing in a fight (skill based).
- **Grapple:** use on `GRAPPLE` links, to reach high ground, and to escape when retreating.
- **Wall-run:** only on links marked as wall-runnable.

**Combat (`bot_aim.gd` and brain).**

- Target selection: closest visible enemy weighted by low health, low armor, and threat (who damaged me recently).
- Aiming: rotate toward the desired aim point at `aim_tracking_speed`, plus an error vector resampled every 0.3 s (seeded noise) of magnitude `aim_error`. Projectile weapons lead the target: `aim_point = target_pos + target_vel * (distance / projectile_speed) * lead_accuracy`. Rockets aim at the target's feet when the target is grounded and within 20 m.
- Weapon choice by distance and ammo: Shotgun under 14 m, SMG 5 to 30 m, Plasma 8 to 40 m, Rocket 8 to 35 m (never under 3 m unless winning), Railgun over 15 m, Blade under 3 m only if nothing else has ammo, Pistol as fallback.
- Fight movement: never stand still. Strafe left or right, switching direction every 0.4 to 1.0 s (random), jump-dodge occasionally, slide-strafe at higher difficulty, and keep a distance appropriate to the weapon.
- Fire discipline: SMG in bursts of 0.3 to 0.8 s, rockets only with line of sight to the target or its feet, railgun only when aim error is under a small threshold.

**Stuck handling.** If a bot wants to move but travels under 0.5 m over 1.5 s: press jump, then strafe randomly for 0.5 s, then request a new path, and after 5 s total, teleport to the nearest waypoint (increment a debug counter; the soak test fails if teleports exceed 2 per bot per 5 minutes).

**Bot debug (F3).** Shows each bot's current goal, target, path length, and speed; a toggle draws their paths as lines in the world.

## 11. Maps

All maps are generated in code by map scripts that extend a common base and use `MapBuilder` helpers. No imported meshes, no hand-built scenes beyond a tiny shell `.tscn` that loads the map script.

**`MapBuilder` helpers:** `box(pos, size, mat)`, `ramp(pos, size, direction, mat)` (prism mesh with a convex collision shape), `stairs(pos, steps, step_h, step_d, width, mat)`, `cylinder(pos, radius, height, mat)`, `wall(a, b, height, thickness, mat)`, `platform(...)`, `trim(a, b, thickness, emissive_color)` (thin emissive strips that make edges readable at speed), `jump_pad(pos, launch_velocity)` (`Area3D` that launches fighters, 0.5 s per-fighter cooldown, glowing pad visual), `grapple_anchor(pos)` (visible glowing nodes, grapple raycast still works on any world surface), `kill_volume(aabb)`, `spawn(pos, yaw)`, `pickup(type, pos)`, `label_sign(pos, text, color)` (`Label3D`). Each helper creates a `MeshInstance3D` plus a `StaticBody3D` with collision on layer `world`. Use `MultiMeshInstance3D` for repeated small props (pillars, rails, crates). Do NOT use CSG nodes (slow, collision quirks).

**Look (`map_palette.gd`).** Flat-colored low-poly with a subtle procedurally generated grid texture (256x256, triplanar, low contrast) on floors and walls, bright emissive trim, `WorldEnvironment` with a gradient `ProceduralSkyMaterial` per map, light distance fog, glow on, filmic tonemap, one `DirectionalLight3D` with soft shadows. Every map ships with a `MapPalette` resource (floor, wall, accent, trim, sky top/horizon, fog color).

**Required per map:** at least 16 spawn points evenly distributed with clearance; at least 20 pickups per the table in Section 8 (all 5 combat weapons, 1 Mega Health, 1 Overcharge, 1 Haste, armor, health, ammo); a kill volume below the playable area; a generated waypoint graph; a name, one-line description, and a top-down preview image generated at runtime (orthographic camera in a `SubViewport`, rendered once and cached in memory) for the match setup screen.

### 11.1 Foundry (industrial pit arena)

- Footprint 80 x 80 m, height 24 m. Palette: charcoal floors, orange emissive trim, dusk orange-purple sky.
- Center: a circular pit (radius 14 m, depth 6 m) filled with a glowing lava surface that is a kill volume. Four 5 m wide catwalk bridges cross the pit at floor level, meeting at a central junction platform.
- An upper gantry ring at y = 8 m runs around the arena, reachable by four corner ramps, stairs, jump pads (launch velocity about (0, 17, 0) plus a small forward component), and grapple anchors.
- Two long smooth walls (north and south, 40 m long, 12 m high) designed for wall-running, with trim lines showing the route.
- Scattered pillars, crate clusters with mantle-friendly heights (1.0, 1.4, 1.8 m), and two raised side rooms with doorways.
- Placement: Mega Health on a small platform above the pit center (y = 4 m, reachable via jump pad or grapple), Rocket Launcher on the NE gantry, Railgun on the SW gantry, Overcharge in a hidden side room, Haste on the south wall-run route, Shotgun west ground, SMG east ground, Plasma on the central junction, armor plates at gantry ends, health around the outer ring.

### 11.2 Spire (vertical tower arena)

- Island radius 28 m with a void beyond (kill volume), tower height about 45 m. Palette: icy cyan and white, bright sky, teal emissive trim.
- A central tower core (cylinder, radius 6 m, height 40 m) with a 6 m wide spiral ramp that winds around it for 3 loops. The tower surface is wall-runnable.
- Eight floating platforms at varied heights (6 to 36 m) around the tower connected by jump pads and grapple anchors. Falling off a platform onto the island is safe; falling off the island is death.
- Placement: Overcharge and Railgun at the very top, Rocket Launcher and Mega Health on mid platforms, health and armor at the base ring, SMG, Shotgun, and Plasma on the lower platforms.
- This map teaches vertical movement; bots must use `GRAPPLE` and `JUMP` pad links to reach upper levels.

### 11.3 Sprawl (neon city speed course)

- Footprint 120 x 60 m with long straights suited to bunnyhopping. Palette: magenta and teal neon dusk, glossy dark road, emissive signs (`Label3D` with generated text).
- Central plaza, two parallel boulevards, three slide tunnels (3 m wide, 2.2 m high, 18 m long, sloped 10 degrees downhill), elevated skywalk network on two levels, large flat building walls (25 m) for wall-running, alleys with mantle crates, and rooftop lines connected by gaps requiring bhop or grapple.
- Optional surf ramp section (see Section 6 FALLBACK note).
- Pickups spread wide so that routes and timing matter.

### 11.4 Practice Range (`map_range.gd`)

- 60 x 40 m hall. West half is a shooting gallery: static, moving (on rails), strafing, and pop-up `TargetDummy` objects at 10, 20, 40, and 70 m. Dummies have 100 health, show floating damage numbers, and respawn after 2 s.
- East half is the movement course: an 80 m bunnyhop straightaway with speed gates (rings that display your speed as you pass), a slide tunnel, a wall-run corridor (two parallel walls, 30 m), mantle crate steps, grapple pillars, and a timed lap with checkpoints. Best lap times saved to `user://records.cfg`.
- A weapon rack with all 7 weapons and a toggle (key T) for infinite ammo. Key F5 spawns a sparring bot (difficulty selectable in the practice HUD), F6 removes it, R resets position, a large speedometer is always on.

**Waypoint graph generation (`waypoint_graph.gd`).**

1. Sample a 3 m grid over the playable bounds; for each cell cast a ray downward to find floors (normal.y > 0.7, clearance at least 1.9 m above).
2. Add a waypoint at each valid floor point (cap about 1200 per map).
3. Link neighbors within 4.5 m: `WALK` if a capsule sweep is clear and height difference is under 0.4 m; `JUMP` if the height difference is up to 1.6 m and the path is clear; one-directional `DROP` if the destination is lower (up to 8 m) and the horizontal gap is small and clear.
4. Add `GRAPPLE` links (from, anchor, to) and jump pad links as declared by the map script.
5. Keep only the connected component that contains the spawn points, and verify every pickup and spawn is within 3 m of a waypoint in that component.
6. Store in an `AStar3D` with link metadata; generate behind the loading screen in under 1 s per map.

## 12. Match flow and rules

**`MatchConfig`:** `map_id`, `bot_count` (1 to 11, default 7), `difficulty` (Rookie, Veteran, Elite, Nightmare, Mixed; default Veteran), `kill_limit` (10, 15, 25, 40, 50; default 25), `time_limit` (3, 5, 8, 10, 15 minutes or unlimited; default 8), `powerups_enabled` (default on), `pickup_respawn_scale` (0.5x, 1x, 2x), `mutators` (set): **Low Gravity** (gravity x0.6), **Instagib** (Railgun only, one hit kills, no pickups except powerups disabled), **Rockets Only** (Rocket Launcher with infinite ammo, knockback x1.5). Instagib and Rockets Only are mutually exclusive. The setup also offers **presets**: Quick Match (defaults), Movement Frenzy (Low Gravity, Elite bots, Sprawl), Rocket Arena (Rockets Only, Foundry), Instagib (Spire), Sweat (Nightmare, 11 bots, 15 minutes).

**State machine (`Game` and `MatchManager`):**

1. **Loading:** build map, generate waypoint graph, spawn fighters, pre-warm particle and audio pools, show progress (yield a frame between steps so the bar animates).
2. **Intro (2.5 s):** orbiting camera over the arena with the map title and mode info; fighters frozen at spawns.
3. **Countdown (3 s):** 3-2-1-GO with tick sounds; the player can look but not move.
4. **Live.**
5. **Overtime:** if time runs out with a tie for first place, sudden death until the next kill.
6. **Ending:** triggered by the kill limit or time limit; the final kill plays at 0.3x time scale for 1.5 s with the winner banner, then the results screen.
7. **Results:** see Section 13.

**Pause.** Escape pauses the whole game (`get_tree().paused = true`), bots frozen, mouse visible. The pause UI uses `PROCESS_MODE_ALWAYS`. Tweens that run in the pause menu must use pause-aware mode.

**Lifetime stats** saved to `user://stats.cfg`: matches played, wins, kills, deaths, best top speed, best kill streak, total grapple distance. Shown on the main menu.

## 15. Audio generation and mixing

All audio is synthesized by code. Write `tools/generate_audio.gd` (run with `godot --headless --path . --script res://tools/generate_audio.gd`) that renders every sound to 16-bit PCM `.wav` files in `assets/audio/` (SFX mono 44.1 kHz, music stereo 32 kHz to keep file size reasonable), then run `godot --headless --path . --import` so Godot imports them. Commit the generated files. **FALLBACK:** if file generation fails, the `Audio` autoload synthesizes the same sounds at startup into `AudioStreamWAV` objects.

**Synth toolkit (in the generator):** oscillators (sine, square, saw, triangle, seeded noise), ADSR envelopes, exponential pitch sweeps, one-pole low-pass and high-pass filters, simple biquad band-pass, bit-crush, ring modulation, comb-filter reverb and feedback delay, soft clipping, normalization to -1 dBFS with a short fade at both ends to avoid clicks. Use a fixed seed so output is deterministic. Generate 2 to 4 pitch variants for frequently repeated sounds.

**Required sound list (names are the `Audio.play_sfx` keys):**

- Weapons: `shot_pistol` (noise burst plus a square sweep 600 to 200 Hz), `shot_smg` (shorter, three variants), `shot_shotgun` (low-passed noise with a 120 ms decay plus an 80 Hz thump), `shot_plasma` (saw sweep 900 to 300 Hz with chorus), `rocket_launch`, `rocket_loop` (whoosh loop for the projectile), `explosion` (layered noise with a sweeping low-pass, 50 Hz sub boom, crackle tail), `rail_shot` (sine sweep 2000 to 200 Hz with ring-mod shimmer and reverb tail), `rail_zoom` (rising whine), `blade_swing`, `blade_hit` (inharmonic metallic clang), `weapon_switch`, `empty_click`.
- Impacts and feedback: `impact_world`, `impact_flesh`, `hitmarker` (1.8 kHz tick, 30 ms), `hit_head` (higher ting), `kill_confirm` (two-tone ding), `damage_taken` (low thump), `heartbeat_loop`, `medal_1`, `medal_2`, `medal_3` (ascending chimes).
- Movement: `jump`, `land_light`, `land_heavy`, `footstep` (four variants), `slide_loop` (filtered noise loop), `wallrun_loop`, `wall_jump`, `mantle`, `grapple_fire` (zip), `grapple_attach` (thunk), `grapple_reel_loop` (rising tone), `grapple_release`, `jump_pad`, `speed_whoosh_loop` (wind that scales with speed).
- Pickups and events: `pickup_health`, `pickup_armor`, `pickup_ammo`, `pickup_weapon`, `powerup_pickup` (big arpeggio), `powerup_respawn`, `pickup_respawn`, `death`, `respawn`, `spawn_protection_end`.
- UI: `ui_hover`, `ui_click`, `ui_back`, `ui_confirm`, `ui_error`, `countdown_tick`, `countdown_go`, `match_win`, `match_lose`.
- Ambience loops per map: `amb_foundry` (machine hum, distant clanks), `amb_spire` (wind), `amb_sprawl` (electric city hum).
- **Music:** `music_menu` (100 BPM chill synthwave), `music_match_a` (138 BPM driving), `music_match_b` (150 BPM intense), `music_results` (short sting, about 8 s). Procedurally composed from a seeded generator: minor pentatonic, chord progression i-VI-III-VII, 16 bars; synthesized kick, snare, hats, sawtooth bass with filter envelope, square arpeggio, and detuned saw pad; the end wraps seamlessly into the start. Set loop mode and loop end in code after loading (`AudioStreamWAV.LOOP_FORWARD`).

**Buses (created in code by the `Audio` autoload):** Master (with a limiter) -> Music, SFX, UI, Ambient. A low-pass effect on a `Muffle` path engages when health is under 20 or when the player is dead (cutoff about 1200 Hz, smooth transition). A light compressor on SFX.

**Playback rules.**

- World sounds use pooled `AudioStreamPlayer3D` (32 players, `unit_size` 8, max distance 80 m, Doppler on for rockets). The local player's own sounds (fire, footsteps, grapple) use non-spatial pooled `AudioStreamPlayer` (16 players).
- Priority-based voice stealing when the pool is exhausted (explosions and kills over footsteps).
- Cap identical sounds to 4 instances within 50 ms. Random pitch variation of +/-5 percent on repeated sounds.
- Music crossfades between menu and match tracks over 1.5 s and ducks 6 dB during intense moments (low health). Looping sounds (slide, wallrun, speed whoosh, grapple reel) fade in and out based on state.

## Appendix A: Godot pitfalls the agent must avoid

1. After adding or renaming a `class_name` script, run `godot --headless --path . --import` (or open and quit the editor) so the global class cache refreshes; otherwise new types are not recognized.
2. Do not give a script a `class_name` identical to an autoload name.
3. Avoid circular `preload` dependencies; use `class_name` and typed references instead.
4. Physics queries (`intersect_ray`, shape queries) belong in `_physics_process` or after awaiting a physics frame.
5. For raycasts to hit `Area3D` hit volumes, set `collide_with_areas = true`, and make sure `monitorable` is enabled on the areas and collision layers match.
6. `move_and_slide()` takes no arguments in Godot 4 and uses the `velocity` property. Read `is_on_floor()` and `get_slide_collision_count()` after the call.
7. UI nodes that must work while paused need `process_mode = PROCESS_MODE_ALWAYS`; tweens need pause-aware mode there too.
8. `Engine.time_scale` affects physics delta; reset it to 1.0 on every exit from slow motion, including scene changes and errors.
9. In headless mode there is no real renderer: do not read viewport textures or depend on screenshots in automated tests.
10. Viewmodel clipping: put viewmodel meshes on a dedicated visual layer, exclude that layer from the main camera `cull_mask`, and render only that layer with a second camera in a `SubViewport` that shares the main `World3D` (so lighting stays consistent). **FALLBACK:** `no_depth_test` materials.
11. `AStar3D` point ids must be unique integers; use `get_available_point_id()` and keep a mapping from waypoint to id.
12. Pool and reuse particle systems, decals, tracers, debris, and audio players. Never `queue_free()` inside hot loops.
13. Lambdas in loops capture variables by reference; use `.bind()` when connecting signals in loops.
14. Create `Resource` configs in code (or generate `.tres` through code), and avoid hand-editing `.tres` or `.tscn` text unless trivial.
15. Generated `.wav` files must be imported before `load()` works; always run the import step after generating audio.
16. Keep scripts cross-platform: use `res://` and `user://` paths, no OS-specific shell commands in game code, and provide both `.sh` and `.ps1` tool scripts.
17. When a Godot error appears in MCP or console output, treat warnings as errors and fix them before moving on.
18. Commit after every green milestone; if a change breaks things badly, revert that milestone's last commit only (never destructive resets of earlier work).
